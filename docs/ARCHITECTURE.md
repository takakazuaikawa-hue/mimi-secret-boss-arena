# 制作・拡張設計

## 採用技術

- React + Vite + TypeScript: 画面とビルド
- XState: タイトル、週、イベント、育成、試合、結末の画面遷移
- Zustand persist: 進行、設定、殿堂、解放記録のローカル保存
- Zod: 選手、技能、イベントの実行時検証
- seedrandom: 周回シードで再現できる乱数
- fast-check + Vitest: 多数シードの周回・戦闘監査
- Motion: 画面と会話の短い遷移
- Howler: 効果音
- Lucide: 操作アイコン

効果音はKenney Casino Audioを使用する。CC0ライセンスは
`public/assets/audio/casino/License.txt` に同梱する。

## 所有境界

- `src/data`: 追加可能な選手、アイテム、大会、共通イベント
- `src/data/routes.ts`: ルートごとの資金、遭遇、注目、敵戦力の調整値
- `src/data/routeEvents.ts`: 支配興行・大混線祭だけで起きる事件
- `src/game/types.ts`: コンテンツと保存データの契約
- `src/game/content.ts`: Zodによる起動時監査
- `src/game/engine.ts`: 週進行、イベント選出、成長、解放
- `src/game/battle.ts`: UIに依存しない戦闘計算
- `src/game/store.ts`: 永続状態とゲーム操作
- `src/game/machine.ts`: 画面遷移
- `src/App.tsx`: 画面と入力

文章追加で進行ロジックを変更しないこと、戦闘調整で保存形式を変更しないことを
基本ルールとする。

## 選手追加手順

1. `characters.ts` に一意なID、能力、4技能、特性、AIを追加する
2. 遭遇、加入、日常、能力回復、危機、解放、後日談を埋める
3. 各場面に対応する週行動と、二つの意味ある選択肢を設定する
4. 4×4ポートレート盤の空きセルへ追加し、ID順とセル順を一致させる
5. `content.test.ts` の総数を更新する
6. `npm test` でID、場面、選択肢重複、全周回シードを監査する
7. 実ブラウザで長い名前、長い台詞、モバイル幅を確認する

## リリース監査

必須:

```powershell
npm audit
npm test
npm run build
```

続いて実ブラウザで以下を確認する。

1. 新規開始から固定導入を完了できる
2. 4行動のどれでもイベントが発生する
3. 選択後に育成・編成・装備が操作できる
4. 公式戦週に賭け、3人編成、オート戦闘、4監督判断が動く
5. 勝敗後に次週または追加戦へ進む
6. デスクトップと390px幅で文字、ボタン、HUDが重ならない
7. ブラウザコンソールにエラーがない
8. 周回終了時に殿堂、解放、ルート、説明省略が保存される

`balanceAudit.test.ts` は各ルート500周と4,560試合を固定方針で流し、
解放人数、解放ゼロ率、事件比率、試合ターン数、采配回数、采配による勝率差を
監視する。新要素追加時はテストの閾値を緩めず、意図した設計変更だけを記録する。
