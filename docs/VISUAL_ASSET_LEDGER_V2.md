## 方針

- 正本は `src/narrative/content/*.json`、`NARRATIVE_REBOOT_PLAN.md`、`WORLD_CONTINUITY.md`。
- 立ち絵は全身・透過・左右反転可能な中立構図を基準にする。
- 一枚絵は「事件の転換」または「人物報酬」を優先し、書類を持つだけのCGを量産しない。
- 動的なチーム構成を固定人物CGへ焼き込まない。
- アルデバラン社は、人物担当者を正本化するまで黒い角封筒だけを共通モチーフにする。
- 生成素材は採用検査後にだけ物語JSONへ接続する。

## 戦闘絵・表示契約 v1（バトル担当正本）

確定日: 2026-08-09

### 結論

- **今すぐ制作してよい戦闘差分は、未制作13人の固有技カットインだけ。**
- 被弾、勝利、敗北、回復、防御、強化、弱体の専用絵は、現行画面に画像切替スロットがないため生成保留。
- 通常戦闘絵15点は再生成しない。移動、攻撃前進、被弾反動、戦闘不能暗転は既存PNGへのCSS演出で表現する。
- 固有技カットインは既存2点と同じ `1672×941 / WebP / 不透明` を正本仕様とする。
- 主要15人が敵側へ回った場合も同じ素材を使えるよう、量産前に画面実装を陣営非依存参照へ直す。これが終わるまで「敵用の別画像」は作らない。

### 量産前の実装前提

1. `characterVisuals` の参照を `unit.side` ではなく `fighterId` の存在で決める。主要15人が敵側でも既存立ち絵・固有技絵を使えること。
2. 将来、被弾・勝利・敗北差分を採用するときは、先に `battleHit`、`battleVictory`、`battleDefeat` のどれを画面が読むか実装・型・フォールバックを確定する。
3. 味方用／敵用を別ファイル化しない。同一素材を配置・モーション・UI色で両陣営に使う。
4. 3対3で人物が縮小されても顔とシルエットが読めることを実画面で確認してから、同じ構図を残り人物へ展開する。

### 固有技カットイン・共通構図

- 画面: `1672×941 px`、横長、WebP、RGB、不透明。透過は禁止。
- 人数: 攻略対象本人1人だけ。ミミ、味方、敵、観客を描き込まない。
- 焦点: 顔・目・固有モチーフを中央40〜60%へ置く。UIの斜めクリップ後も顔と手が欠けない。
- ポーズ: 技が命中した結果ではなく、**発動を宣言した瞬間**。対象の負傷や勝敗を先取りしない。
- 背景: 人物固有の抽象空間または技の気配。通常の闘技場背景を描き直さない。
- 文字: 技名、擬音、ロゴ、魔法文字を含め、読める文字を画像へ焼き込まない。技名はUIが重ねる。
- 方向: 左右どちらの陣営でも使える中央構図。強い進行方向、片側だけの余白、敵の影を固定しない。
- エフェクト: 顔、手、武器、人物固有輪郭を隠さない。画面外へ伸びる光や粒子は可。
- 色: 人物固有色を主役にしつつ、白い技名UIが読める暗部を最低30%残す。
- 納品: 元画像のほかに、縮小表示で顔・固有モチーフ・ポーズが判別できるか確認する。

### 将来差分の予約名（生成禁止）

画面実装が先に採用された場合だけ、以下の名称を使う。

- 被弾: `public/assets/battle/fighters/{id}-hit-v1.png`
- 勝利: `public/assets/battle/results/{id}-victory-v1.png`
- 敗北: `public/assets/battle/results/{id}-defeat-v1.png`

予約差分は `1024×1536 px / PNG / RGBA透過` を基本とし、通常戦闘絵と足元基準、頭身、衣装、左右余白を一致させる。被弾絵にダメージ数字・血・衝撃エフェクトを焼き込まない。勝利・敗北絵に報酬、順位、対戦相手、固定チームを描き込まない。

## 採用検査

- 透過立ち絵: RGBA、四隅透明、輪郭欠損なし、緑／紫フリンジなし、手指と足先を原寸確認。
- 背景: 人物なし、読める文字なし、左右に立ち絵領域、会話UIで重要物が隠れない。
- 一枚絵: 何が起きているか3秒で説明できる、選択結果を先取りしない、正本の衣装・形態・関係性と一致。
- すべて: ロゴ、透かし、余分な指、融合した小物、別人化を不採用とする。
