# バトル体験基準 v4

## プレイヤーへ約束する面白さ

戦闘の主役は数値計算ではなく、育てた裏ボスが「そのキャラらしい判断」で戦う映像ドラマを見ること。
普通の対戦相手との格の差は格好よさと笑いにし、強敵戦では育成と編成の答え合わせにする。

## 制作時の絶対順序

1. この瞬間にプレイヤーへ何を見せ、何を感じさせるかを決める。
2. 構え、間、カメラ、移動、衝突、表情、実況で一つの短い場面を設計する。
3. プレイヤーがどこを見て判断するかを決め、その視界をUIで塞がない。
4. 必要な判断だけを操作へ落とし込む。
5. 最後に計算、フラグ、AI、数値表示を場面へ従属させる。

計算結果を正しく表示しただけでは未完成。静止画で情報が読めても、時間の流れとして
驚き、緊張、期待、安堵が起きなければ戦闘体験として不合格とする。

## 一手の五拍

1. 予兆: 行動順、行動者、狙われる相手が先に読める。
2. 発動: 全身キャラと技名を大きく見せる。
3. 衝突: キャラが移動し、相手が反応し、短い停止と効果音で重さを出す。
4. 結果: ダメージ、HP、強化・弱体化の変化を対象の反応と同じ場所へ表示する。
5. 学習: なぜ有効だったかを一文で示し、次の編成・育成目標へつなげる。

### 時間順の不変条件

- HP、状態、ダメージ数字は、技が相手へ接触した瞬間まで変化させない。
- クリック直後に結果だけを確定し、その後でキャラクターを動かしてはならない。
- 攻撃は「予備動作 → 踏み込み → 接触と被弾 → 着地」の順に同期する。
- 攻撃対象だけに敵色の照準を出す。自己特性、回復、強化、監督支援へは出さない。
- AUTOでも同じ時間順を保ち、待ち時間だけを短縮する。

## 画面の優先順位

1. 戦っているキャラクターの全身と反応
2. 次の行動と現在の技
3. HP、MP、状態変化
4. 監督介入
5. 詳細ログ

常時表示する情報を増やさない。説明は必要な瞬間に一つだけ出す。監督指示を出す間も
キャラクターと相手の予兆を画面の過半で見続けられること。

「試合の流れ」は双方の現在HP比から出す。「勢い」は連携技へ使う味方資源であり、
優勢・劣勢の判定へ流用しない。二つを同じゲージや同じ文言で表さない。

## 初戦の演出目的

- ギドノゼアースは封印形態の大きな立ち絵で見せる。
- 新人モンスターは小さく、かわいく、真剣に戦う。
- 最初の一手は「黒星」。普通の盾では受け止められない格の差を見せる。
- 戦力予想は実数と出場人数から計算し、「圧倒的有利」と正しく伝える。
- 勝利後に、魔力と技威力が勝因だったと短く説明する。

## 再生方針

- 手動: 一手の結果をクリックして読む。初回既定値。
- AUTO: 一手の五拍を省略せず自動で送る。
- 監督局面: AUTOでも必ず停止する。
- 速度変更は待ち時間だけを縮め、情報自体は消さない。

## 実況規則

- 試合開始時は必ず「大会名 -> 相手全員 -> 味方全員 -> 第1ターン開始」の順で紹介する。
- 通常実況は「○○の攻撃」「○○にNダメージ」「特性で防御が上がった」のような
  既存RPGで意味が通じる定型を優先する。詩的な言い換えで結果を隠さない。
- 実況は内部状態の説明ではなく、闘技場に実在する実況兼審判が話す劇中の言葉とする。
- 映像があるため、ラジオのように見えている動作を全部読み上げない。異変、狙い、衝突の
  大きさ、相手の反応、試合が動いた瞬間だけを短く補う。
- 技の前は一文、衝突後は一文を基本とし、キャラクターの動きと効果音の間を奪わない。
- 大技の個性はカットイン、技名、音、対象の反応で見せる。実況は結果を明瞭に保つ。
- 「AI」「行動予告」「結果待ち」「注目」「対象」「判定」など、制作側の分類語を
  プレイヤーへ表示しない。
- 実況は画面下の放送帯へ置き、キャラクターの全身、相手の反応、技の軌道を隠さない。
- 同じ状況へ複数の短い言い回しを持たせ、長い台詞ほど一試合の使用回数を減らす。

参照方針: 実況は画面に映る行動を追う play-by-play と、重要な作戦結果だけを語る
color commentary に分ける。TV型実況として、見えている情報を過剰に復唱しない。

## アート方針

- 味方は全身立ち絵。1対1ほど大きく見せる。
- 敵は専用スプライト。普通の敵はかわいく、ボスは大きく異形にする。
- HUDはキャラの足元へ固定し、攻撃移動には追従させない。
- 技固有の演出は色だけに頼らず形も変える。これは視覚表現であり、属性相性や倍率は持たせない。
