# 改修ロードマップ

最終更新: 2026-07-31

本書は改修の順序、依存関係、完了条件、作業記録を管理する。作業は番号順を原則とし、
後工程を先に行う場合は理由と手戻りリスクを記録する。

## 1. 順序の原則

1. 体験基準を固定してから仕様を直す。
2. ノベル体験の全体構造を決めてから、育成や戦闘の細部を決める。
3. 最初の数週間を完成品質の縦切り体験にし、面白さを確認してから全編を量産する。
4. データ契約と保存形式を固定してから画面とイベントを増やす。
5. 育成と戦略はライト層が物語を楽しむための変化、緊張、周回差として設計する。
6. 戦闘の判断モデルを直してから、その因果を伝える演出を載せる。
7. 人物の物語を文章で確定してから一枚絵を生成する。
8. 共通UI基盤を作ってから全画面を同じ品質へ揃える。
9. 機能単体ではなく、90分の一周と周回後まで通して完成を判断する。

## 2. 改修フェーズ

### Phase 0: 製品理解と基準統一

目的:
過去文書、実装、ユーザー意向の矛盾を除き、以後の判断基準を一つにする。

作業:
- `PRODUCT_DIRECTION.md` を最上位基準として確定する。
- 既存設計書の矛盾、古い自己採点、撤回済み仕様へ明示的な無効表示を付ける。
- 全要求を「確定」「要確認」「非採用」に分類する。
- 全画面と全機能を、ノベル体験を強めるもの、支えるもの、妨げるものに分類する。

完了条件:
- 大目的、対象プレイヤー、体験優先順位、画面基準、不変条件に矛盾がない。
- 修正判断がどの文書に従うか一意に決まる。

### Phase 1: ノベル体験の全体設計

目的:
本作でしか読めない面白さを、設定の量ではなく、一周の読書体験として設計する。

作業:
- 一周の感情曲線を、驚き、笑い、接近、危機、試合、結末の順で設計する。
- プロローグから最初の能動選択、最初の人物への興味、初試合までの導線を決める。
- ミミの語り口、コメディの発生構造、乙女ゲーム文法の扱いを固定する。
- 各人物の「人へ話したくなる固有場面」と、人物同士で重複しない魅力を定義する。
- 選択肢が変える短期反応、中期展開、結末への影響を設計する。
- 契約、支配、解放は固定テーマではなく、現行プロット上の演出として再評価する。
- ミミの共通物語として、派遣、前オーナー、偶発的な引継ぎ、権利の段階発見、
  各大会へ出る個別の動機を一続きに設計する。

完了条件:
- 一周を場面一覧だけで追っても、退屈な区間と感情の山が判別できる。
- 各主要人物に、笑い、意外性、心理の深まり、クライマックスが一つ以上ある。
- 育成や戦闘を除いても読みたい物語の核が説明できる。

### Phase 2: コンテンツ構造、状態遷移、保存・QA基盤

目的:
Phase 1の物語を安全に増やし、分岐、回想、周回を壊さず届ける土台を作る。

作業:
- キャラクター、場面、選択、記憶、立ち絵、CG、音、試合挿入のデータ契約を定義する。
- 5,000行超の画面実装を、物語表示、ゲーム状態、画面単位へ分割する計画を確定する。
- 保存データをスキーマ検証し、版管理、移行、破損回復、新規開始確認を実装する。
- 開発用シナリオジャンプと再現可能な固定シードを整備する。
- 分岐到達、テキスト欠落、画像欠落、回想解放を検査する仕組みを作る。
- 画面単位の視覚回帰を取れるテスト環境を安定化する。

完了条件:
- 新規開始で進行中データを無警告に失わない。
- 古い保存、破損保存、再読み込みを安全に扱える。
- 主要場面へテストから直接到達し、分岐と演出資産の不足を検出できる。

### Phase 3: 最初の数週間の完成品質縦切り

目的:
全編を作り直す前に、本作の中心的な面白さを短い実プレイで証明する。

作業:
- プロローグ、派遣初仕事、前オーナー、ギドノゼアースとの遭遇、権利引継ぎ、
  勧誘判断、日常を完成稿にする。
- 最初の公式戦までを、物語、選択、ライトな育成、試合、結果まで通して作る。
- 立ち絵、一枚絵、背景、音、選択肢、クリック送りを仮素材ではなく完成基準で揃える。
- 初見プレイヤーに遊んでもらい、笑った場所、混乱した場所、続きを読みたい理由を記録する。

完了条件:
- 育成や設定説明ではなく、物語と場面を理由に続きを遊びたい反応が得られる。
- 初回の選択と試合を、戦略ゲーム未経験者が説明なしで進められる。
- この縦切りを品質テンプレートとして残りの人物と週へ展開できる。

### Phase 4: ライト層向けコアループと育成

目的:
週行動、育成、資金、賭け、試合を、物語の期待と周回差を作る親切な手法にする。

作業:
- 第1週と第3週までの加入保証を、行動ごとに公平で魅力的な導入へ作り直す。
- 働く、遊ぶ、休む、探すを、物語予告と明確な利益から直感で選べるようにする。
- 固有Pと共有P、装備、体調を、推奨と自動配分を備えた段階開示にする。
- 資金と賭けは逆転の楽しさを作り、失敗しても物語進行を止めない。
- 通常、支配、大混線の差を、難度だけでなく起きる物語の差として成立させる。
- 連続キャンペーンで、選択、人物進行、試合、結末の関係を検証する。

完了条件:
- 戦略ゲーム未経験者が、推奨に従うだけでも最後まで物語を読める。
- 慣れたプレイヤーには編成と育成で改善する余地がある。
- どの週行動も、物語上とゲーム上の両方で選ぶ理由を持つ。

### Phase 5: 読んで理解できる監督型戦闘

目的:
戦闘を物語の山場として楽しみ、ライト層が結果から自然に学べるようにする。

作業:
- 技選択と対象選択の実際の判断理由を戦闘ログへ記録する。
- 能力、役割、技、状態変化を絞り、推奨編成と役割の説明を用意する。
- 七つの公式戦へ固定の敵編成、象徴技、分かりやすい攻略の学習順を作る。
- 接近、攻撃、命中、回避、被弾、BREAK、退場、帰還の動作文法を作る。
- AIが選ぶことと、演出をプレイヤーがクリックして読むことを分離する。
- 戦後に有効だった準備、危険だった相性、次の改善候補を示す。
- 最終大魔王を専用データ、段階変化、予兆、技、演出、物語で実装する。

完了条件:
- 初見の一戦を見た人が主要な出来事を時間順に説明できる。
- 推奨編成で遊べ、興味を持った人は自分の作戦で勝率を改善できる。
- 試合が文章の中断ではなく、人物と物語のクライマックスになっている。

### Phase 6: 全人物の物語と選択肢

目的:
縦切りで検証した文章と演出の品質を、全人物と一周全体へ展開する。

作業:
- ミミの語り、各人物の声、世界説明の順序をキャラクターバイブルへ固定する。
- 各人物の出会い、接近、すれ違い、不信、興奮、危機、クライマックス、後日談を書く。
- 選択肢の即時差、中期回収、結末への影響を場面ごとに実装する。
- メタ発言、唐突な文脈、説明不足、テンプレ重複を全件校閲する。
- 後日談をクリック送りの到達可能な場面として実装する。
- 全人物を人間が通読し、笑い、感情、固有性、勧めたくなる場面を記録する。

完了条件:
- 全人物の物語で、情景、感情、動機、変化、選択の回収が理解できる。
- 選択肢を隠し数値なしでも選びたくなる。
- 一枚絵の制作前に全重要場面の脚本と画面指示が固定される。

### Phase 7: UI基盤、ビジュアル資産、物語演出

目的:
確定した物語とシステムを、全画面で同じ商業品質のノベルゲームとして届ける。

作業:
- 色、文字、余白、階層、選択肢、台詞枠、モーダル、モーションの共通規格を作る。
- 週行動、人物詳細、育成、編成、装備、試合準備を同じ品質へ揃える。
- 全身立ち絵、表情、真の姿、縮尺、透明余白の資産規格を作る。
- 既存人物を異形比率と設定に照らして再監査する。
- 各人物の出会いと重要転換点のショットリストを確定する。
- 一枚絵を生成し、顔、手指、衣装、種族、装飾、光源の一貫性を検査する。
- 閲覧済み画像をギャラリーへ自動登録し、原寸表示を検証する。
- 1280x720、1280x800、390x844の固定回帰画像を作る。
- 巨大CSSの重複と順序依存を画面移行に合わせて除去する。

完了条件:
- 会話中に適切な全身立ち絵が常に表示される。
- 全人物の重要な感情変化に固有の視覚的な山場がある。
- 画像破綻と人物不一致を原寸と実画面の両方で検査済み。
- 全主要画面に重なり、欠け、意図しない余白がない。

### Phase 8: 周辺体験、周回後、音、性能

目的:
タイトルから終了後まで、ゲームとして欠けている体験を埋める。

作業:
- ローディング、待機、結果、エンディング、記録室を共通品質へ揃える。
- 殿堂チームのフリー対戦と過去チーム大会を実装する。
- タイトル、日常、人物、試合、結果のBGM、環境音、効果音を設計する。
- 画像を適切な形式と寸法へ変換し、場面単位で遅延読み込みする。
- キーボード、フォーカス、コントラスト、文字サイズ、動き軽減を検証する。

完了条件:
- 周回後の保存チームを実際に選んで戦える。
- 初回ロード、画面遷移、長時間プレイが性能予算内に収まる。
- 音なしでも遊べ、音ありでは場面の感情が明確に強くなる。

### Phase 9: 完走監査と調整

目的:
個別機能ではなく、製品全体をプレイヤー体験として完成させる。

作業:
- 初見の人間速度で90分を通し、理解、迷い、退屈、期待、感情を時刻付きで記録する。
- 二周目の説明省略、別方針、別人物、別ルートを確認する。
- 全敗、資金0、少人数、解放なし、保存破損などの負経路を通す。
- 全画面、全人物、全試合、全結末、周回後をデスクトップとモバイルで確認する。
- 未完了監査を再監査し、証拠のない点数を付けない。

完了条件:
- `COMPLETION_AUDIT_2026-07-28.md` の全項目が証拠付きで閉じている。
- 重大度High以上の既知欠陥が残っていない。
- 90分プレイ後に、次周で試したい具体的な目標がプレイヤーの言葉で出る。

## 3. 実装依存関係

後工程の都合で上流を仮決めしない。各層は、直上の層の契約と完了証拠を使う。

```text
製品基準・対象プレイヤー
  -> 一周の物語構造と人物固有性
    -> 正式なイベント／選択／演出データ
      -> 発生条件と状態遷移
        -> 保存・移行
          -> 実行器
            -> 物語画面・週行動・戦闘への表示
              -> 編集・監査・シナリオジャンプ
                -> 自動テスト・実画面・人間速度の完走
```

| 層 | 現在の正本 | 状態 | 次のゲート |
| --- | --- | --- | --- |
| 製品基準 | `PRODUCT_DIRECTION.md` | 確定 | ユーザーの新しい意向だけが上書きできる |
| 一周構造 | `NARRATIVE_MASTER_PLAN.md`、`WEEKLY_EXPERIENCE_MATRIX.md` | 要再照合 | 冒頭完成稿と26週の因果を一致させる |
| データ契約 | `NARRATIVE_DATA_ARCHITECTURE.md`、`src/narrative/schema.ts` | 実装済み | 正式データで仮IDを使わない |
| イベント本文 | 導入2場面とギドノ全7場面は正式JSON、残り184ブロックは旧`CharacterScene`と互換アダプター | 互換移行中 | ギドノ7場面を文章・選択・演出の品質テンプレートとして通読監査する |
| 発生条件 | `engine.ts`の選出ロジックとブロック`trigger` | 二重管理 | 候補理由を監査できる選出器へ統一する |
| 物語状態 | `flags: string[]`、`eventHistory`、人物状態 | 互換移行中 | 型付きStoryStateと訪問回数へ移す |
| 保存 | Zustand persist v9、旧ID補完 | 部分完了 | スキーマ検証、破損回復、nodeId保存を追加する |
| 実行 | `src/narrative/runtime.ts` | 互換実行済み | 分岐後本文、外部ジャンプ、予約イベントを正式対応する |
| 表示 | `CharacterScene`へ投影して既存UIで表示 | 互換移行中 | ノード単位再生へ移し、画面指示を完全に扱う |
| 編集 | 編集ツールschema v2 | 部分完了 | 改訂JSONの検証・安全なソース反映を実装する |
| 自動QA | 構造監査、保存移行、固定シードテスト | 部分完了 | 候補到達、分岐網羅、破損保存を追加する |
| 実画面・人間QA | 過去監査のみ | 未完了 | 負荷管理後に固定3画面幅と90分完走を実施する |

### 移行中に守る不変条件

- 互換変換できたことを、正式データ化の完了とは呼ばない。
- 自動テスト成功を、実画面確認や文章品質の完了とは呼ばない。
- 旧セーブを読める間は互換IDを保持するが、新規履歴は永続IDで記録する。
- 文章確定前に一枚絵を量産しない。
- 表示層の都合で物語、選択結果、加入・解放条件を変更しない。
- CPU負荷の高い全体ビルド、ブラウザ自動操作、全件画像走査は、目的と回数を
  明示してから一度ずつ行う。
