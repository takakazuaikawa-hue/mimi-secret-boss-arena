# 一　メインストーリー執筆規約（MAIN_STORY_WRITING_RULES.md としてそのまま置ける形）

対象は `src/narrative/content/main.s*.{ep,w}*.json` のメイン各話。人物別ファイル（meet/join/bond/power/crisis/liberation/epilogue）は本規約の §1〜§3 と §7 のみ適用し、§5 の「シーズンの問い」はメイン側が持つ。
本規約は `docs/TEXT_BIBLE.md`（文章の基準）と `AGENTS.md`「プレイヤー向けUI・物語マニフェスト」の下位規約であり、衝突したら上位が勝つ。

---

## 0. 用語と単位

- **一話** = 1個の JSON ブロック。`line` ノード **12〜17個** ＋ `choice` ノード1個 ＋ `end`。
  (改定 2026-08-14: 当初の7〜9個はランダムイベントの尺で、メインには短すぎるとの
  ユーザー指摘により増量。ランダム・人物場面は従来の7〜10個のまま)
- **一行** = `line` ノード1個。本規約の「行1〜行9」の型は役割の順序であり、増量時は
  承(行3〜4)と転(行5〜6)の役割を複数ノードに分けて膨らませる。起と引きは薄めない。
- **一話の総量** = 本文 **1400〜2200字**。1ノード **60〜140字**、山場ノードは40字台まで
  落としてよい。会話の応酬・場面転換(背景切替)を含め、一話の中で呼吸を作る。

## 1. 一話の構造の型（何を、どの順で、何文書くか）

### 1-1. 固定テンプレート（全話これで書く）

| 行 | 役割 | 文数 | 必須要素 |
|---|---|---|---|
| **行1** | 接地 | 2〜3文 | いま身体に来ている刺激（**非視覚から**）／場所と時刻が行為の中に一語二語で入る／**前話から持ち込んだ物**がここに写る |
| **行2** | 目的と前提 | 2〜3文 | 「今日ミミがここへ取りに来たもの」を読者に分かる形で言う。**同時にミミの前提を1文で言い切る**（「〜のはずだ」「〜という仕事だ」） |
| **行3** | 行動 → 世界の反応（一回目） | 2〜3文 | ミミが動く。世界が返す。**今週の遊び（ボケ）の1回目** |
| **行4** | 障害の強化 | 2〜3文 | 同じ抵抗の反復ではなく**一段強い**抵抗。**遊びの2回目**（同じ形・より大きく） |
| **行5** | 転(1) ギャップ | 2〜3文 | 期待と結果のあいだが開く。ミミの前提（行2）が通用しない証拠が出る |
| **行6** | 転(2) 認知＋逆転 | 2〜3文 | **既に知っていたことの意味が変わる。** 新事実の追加では不可（§8-3） |
| **行7** | 結＝破綻 | 2〜3文 | 「いいえ、しかも」か「はい、しかし」で着地。**遊びの3回目でパターンを外す**（三の法則） |
| **行8** | 反応 | 1〜2文 | **感情 → 反射 → 理性的行為/発話**の順。順序は入れ替えない |
| **行9** | 引き | **1〜2文・その話の最短ノード** | §3 の型から1つ選ぶ。断定で終わらない |
| **choice** | 決断 | label 20字前後 / result 150〜250字 | §1-3 |

- 行数を7に縮めるときは、行4か行5を落とす。**行1・行2・行6・行7・行9は絶対に落とさない。**
- 行3〜行7のあいだの接続語は、必ず「**だから**」か「**しかし**」。「そして」しか入らない箇所が2つ以上あったら、その話は場面ではなく出来事の列なので書き直す。

### 1-2. `emotion` の配り方（schema の enum に対応）

`comic` を骨、`tension` を行4〜5、`revelation` を行6、`resolve` か `tender` を行7〜8、行9は基本 `tension` か無指定。**1話に `resolve` を2つ置かない**（着地感が二重になり、引きが死ぬ）。

### 1-3. 選択肢（`choice`）

- 行9で提示した**両立不能な二つの価値のどちらを捨てるか**にする。「同じ目的への別手段」にしない。
- `label` は20字前後、**何をするかが分かる形**。制作用語・分類語を入れない。
- `result` は「**決断 → その場の世界の反応**」。報告書にしない。「あなたが選んだ」「今週の結果」型の可視ラベルは禁止（マニフェスト準拠）。
- 結果は原則「**はい、しかし**」。選択は成功させ、代価か副作用を返す。「いいえ」は世界が有意に変わるときだけ。
- `intent` は**動機の宣言**を1行（「分からないことを、その場で聞く」形式。現行 ep1 の書き方でよい）。
- `promise` には**得るものと代価の両方**を書く。得るものだけ書かない。
- `memory` は**3〜5話後に人物の台詞で参照するための台帳**として書く。参照予定のない `memory` を書かない。
- 明らかな上位選択肢を作らない。片方が「正解」に見えたら、弱いほうに固有の見返りを足す。

## 2. 情景描写の作法

### 2-1. 数値基準（機械検査可能）

| 項目 | 基準 |
|---|---|
| 一文 | **40字以内**。1話に3行以上の長文は0本 |
| 漢字使用率 | **20%以下** |
| 非視覚の知覚（匂い・手触り・温度・重さ・味・平衡感覚） | **1話に2つ以上** |
| フィルター語 | 1話 **3個以下**（下記リスト） |
| 「〜と思った」型の直接心理 | **1話1回まで** |
| 比喩（「〜のような」「〜みたいな」） | **1話1回まで** |
| 「そして」 | 1話1回まで |
| 「……」 | 1話3回まで |
| 「——」(ダッシュ) | 1話5回まで(改定2026-08-15: 実運用の文体に合わせ緩和。連続する行での連用は不可) |
| 新規固有名詞 | **1話1個まで**（§4） |
| 説明の連続 | **2行・150字まで**。3行連続の設定説明は禁止 |
| 同じ文末（〜た。〜た。〜た。） | **4連続禁止** |

### 2-2. フィルター語・思考動詞の禁止リスト

**削る**：〜が見えた／〜が聞こえた／〜を感じた／〜に気づいた／〜と思った／〜だと分かった／〜のようだった／〜な気がした／〜らしい（**例外：ミミのツッコミの「らしい」だけは残してよい**。認識の遅れが笑いの機構だから）

**外形へ展開する**：知る・分かる・信じる・望む・思い出す・想像する・愛する・憎む／「不安だった」「嬉しかった」

- 悪：`私はシャルルが何かを隠していると気づいた。不安だった。`
- 良：`シャルルは名簿を閉じた。閉じてから、もう一度ページの端を指で押さえた。押さえる必要のない厚さだった。`

### 2-3. このゲーム固有の役割分担（重要）

**背景画と立ち絵が視覚を担当する。地の文は非視覚を担当する。**

- 見えているものをそのまま書かない。書くなら**後で回収する一点**だけ。
- 「歓声が聞こえた」→「**歓声で背中の毛が立った**」。音は「体で受けた感触」に変換する。
- 状況転換を「〜が終わった」「〜へ向かった」と報告しない。**扉・風・匂い・音の消失**で切る。
- 背景・立ち絵・表情と、本文の場所／時刻／行為が食い違ったらバグとして扱う（マニフェスト準拠）。`presentation.assets` の `alt` と本文を突き合わせてから確定する。

### 2-4. 場面の立ち上げ（行1の五文型）

1. いま身体に来ている刺激を**名詞から**、非視覚優先（「更衣室は、洗剤と砂の匂いがする。」）
2. 身体の反応（「前掛けの紐が硬くて、二回結び直した。」）
3. 定位を**行為の中に一語二語**（「朝礼まで、あと少し。」）
4. ミミの解釈＝声・ギャグ・判断
5. 行2へ渡す

### 2-5. 一人称の物理制約

- ミミは自分の顔・表情・背中を描写しない。必要なら**鏡・水面・実況モニター・他人の台詞**を使う（「顔、真っ白だぞ」）。
- ミミが興味を持たない対象は**意図的に描写を削る**。描写量そのものがミミの人格表現になる。

## 3. 引きの作り方と類型

### 3-1. 大原則

- **今週の話は閉じる。連続要素は必ず1本、閉じずに残す。** 両方できていない話は不合格。
- **「上出来の一日だったと思う」型の完全着地を全話で禁止。** 現行 ep1 の最終ノードがこれで、これが最大の欠陥。
- 最後の一文は**問いか予感**。断定で終わらない。
- **台詞だけで終わらない。** 台詞の直前か直後に動作か知覚を1つ置く。
- 引きは**安堵ではなく静止**を作る。

### 3-2. 型（8種。毎話1つ選び `debug.authorNote` に型名を記録）

| 型 | 中身 | 読者に残る問い |
|---|---|---|
| `決断の直前` | 選ぶ瞬間で切る | どっちを選ぶ |
| `半分の啓示` | 開いたところまで見せ、中身を見せない | 何が入っていた |
| `保留された返事` | 問われて答えない／答えが返らない | 何と答える |
| `次に会う理由` | 約束・呼び出し・場所だけが残る | 何が起きる |
| `未決着の勝負` | 勝敗が付かないまま切れる | どちらが勝つ |
| `うっかりの約束` | 断れない約束をしてしまった状態で切る | どう払う |
| `恥の予兆` | 露見が確定し、実行前で切る | どう見られる |
| `閃き` | ミミが何かに行き当たる。意味は次話まで伏せる | 何に気づいた |

**コメディ作品の基本形は「うっかりの約束」と「恥の予兆」。** 命の危険で引かない。

### 3-3. 切断位置（型と併記して記録）

`pre-point`（転換点の直前）／`climactic`（開示と行動のあいだ）／`post-point`（転換点の直後＝「なぜ?」を残す）／`post-hook`（収束後に新しい発端）。
**世界の発見回は `post-point` を優先。** 同じ切断位置を3話連続で使わない。

### 3-4. 大きさの配置

- **小**（気づく／思いつく／話し始める）＝通常週
- **中**（誰かが近づく／声をかける／返事を保留する）＝大会前週・大会翌週
- **大**（目的が閉ざされる／核心が動く）＝**週6・週13・週20・週25・週26 のみ**

**強い引きは5話に1回でよい。** 全話を煽りで締めない。

### 3-5. 引きの禁止事項

1. **「近づいてくる誰か」の正体を書かない。** 正体が分かる引きは引きとして機能しない。
2. **次話の冒頭1〜2行で前話の危機を無効化しない**（クリフハンガー撤回）。危機を出したら実害を出す。出せないなら危機として書かない。
3. **中身のない煽りを置かない**（血だと思ったらケチャップ）。ただし直後により悪いことが起きるなら可。
4. **引きで言及したことは必ず後で実現させる。** 実現予定のない不穏な一行を置かない。

## 4. 読者への情報提示の作法

### 4-1. 固有名詞・新概念

- **1話に新規固有名詞は1個まで。**
- 初出は、**同じ `line` ノードの中で、それが使われて結果が出るところを見せる。** 定義文を書かない。
  - 悪：`〈黒封筒〉が届いた。この街では指名試合の招待状を意味する。`
  - 良：`封筒は黒かった。受付係さんが目を逸らした。「受け取ってしまうと、断れないやつです」`
- 合否判定：**そのノードだけを読んだ初見プレイヤーが「それの何が問題か」を言えるか。** 言えなければ書き直すか、その語をその話から抜く。
- 名前だけ出して機能を次話へ持ち越さない。
- 説明台詞は**話者に「それを言う動機」を持たせる**。相手を動かすため、金を取るため、責任を逃れるために言わせる。目的のない説明台詞は削る。

### 4-2. 読者が常に持っていなければならない5点

各話の冒頭で、初見プレイヤーが次を把握できていること。欠けたまま謎を足した話は**バグとして扱う**。
①ミミが今週何を切実に欲しているか ②失敗したら何を失うか ③どこ・いつか ④中心の障害は何か ⑤この作品の色（コメディであること）

**隠してよいのは「結果と意味」であって、「読者にとっての文脈」ではない。** 混乱は謎ではない。

### 4-3. 爆弾は先に見せる

- 対戦相手の切り札・罰則・期限は、**ミミより先に読者へ渡す。**
- **各シーズンに「ミミが知らないことを読者だけが知っている」状態を常時1本以上維持する。** これがないと引きは構造的に発生しない。
- ミミが知覚した事実を「見た瞬間、言葉を失った」と伏せるのは契約違反。伏せるのは意味だけ。

### 4-4. 謎の台帳

新しい謎を出すときは、`debug.authorNote` に「**投げた週／答える週／答えの実体**」を書く。
- 答えが決まっていない謎は書かない。
- 答えは「論理の解答」ではなく「**誰の何が変わる出来事**」の形で用意する。1行で書けないなら没。
- **同時に開いている糸は3〜5本まで。** 6本目を出す前に1本閉じる。
- 開いた順の**逆**で閉じる（世界の謎を閉じる前に、その内側の人物の探求を閉じる）。

## 5. 連続性を作る装置

### 5-1. 前話を今話に効かせる（3点セット・必須）

1. **物で持ち込む。** 直前3話でプレイヤーが実際に触れた**具体物・人物・数字**を1つ、行1〜行2に実体として出す。「先週わたしは〜した」という要約は禁止。
2. **未回収の原因を1本だけ垂らす。** 各話の行9で開いた原因を、**次話の行1〜行2で受ける。** 受けたことが分かる語を再出させる。
3. **前提の更新を持ち越す。** 行6でミミの前提が壊れたら、**次話の行2でミミは更新後の前提で振る舞っている。** これが「知識が増える」と「理解が深まる」の差の実体。

### 5-2. 選択の効かせ方

- 選択の結果は独立画面にしない。**次の場面の冒頭で世界の反応として返す。**
- さらに `memory` の内容を **3〜5話後に人物の台詞で一度参照する**（遅延した支払い）。
- 分岐を増やさない。二択は筋を割らず**動機の宣言**にし、**どちらを多く選んだかの累積**を周回後半と結末に反映する。

### 5-3. 反復（様式美）

- **天丼**：ミミの決め台詞・決め行動を、週をまたいで同じ形で繰り返す。1周に3回以上。
- **かぶせ**：他キャラがそれを真似る・上塗りする。天丼が2回出た後に置く。
- 運用は3段：**確立 → 補強 → 裏切りか上昇**。同じ形のまま4回目を出さない。
- **固定するのはキャラの様式（決めポーズ・決め台詞・毎回やってしまうこと）だけ。** 場面の書き出し書式を固定するのは禁止（予告編化＝既知の失敗）。

### 5-4. シーズンの問い

- 1周につき **Yes/No で答えられる一行の問い**を1本決め、全話の `debug.authorNote` に同じ文字列で記録する。
- 各話について「**この話はその問いにどう作用したか**」を1行書けなければ不採用。
- 問いは**ミミ以外の人物が、そのシーズンの第2話で一行の台詞として言う。** ミミはその時点で理解しない。週13で半分わかり、週26で全部わかる。
- 5話ごとに、問いに対する**新しい制約か反証**を出す。

## 6. コメディの積み方

1. **一話一遊び。** その週の「最初におかしなこと」を1つ選び、それだけを掘る。無関係な遊びを2つ入れない。
   （現行 ep1 は竜のチップ／腕相撲決着／経理課の3つが別々で、蓄積していない。）
2. **三の法則。** 同じ遊びを3回。1回目で提示、2回目で強め、**3回目で外す。3回目が一番おかしいこと。**
3. **フリ→オチ。** オチの直前に「きっとこうなる」と読者に思わせる一行を必ず置く。フリのない笑いは書かない。
4. **役割固定：世界と裏ボスがボケ、ミミがツッコむ。** ツッコミは**短文で切る**。ミミが説明を始めるとテンポが死ぬ。ミミがボケる回は「様式を崩す回」として意図的に配置（1周に2〜3回）。
5. **ちゅどーん相当を1〜2個持つ。** 負け・破産・失敗のとき、ミミが余裕を見せる決まった形を作り、痛みを様式化して抜く。擬音はギャグ場面はひらがな、シリアス場面はカタカナ。
6. **感動は独立した回にしない。** 笑いの回の中に**1行だけ**、優しさか痛みが通る行を置く。「今回は感動回」を作らない。
7. **各話の感情は一つに絞る。** 笑いの話に感動を混ぜない。重い話の直後は軽口で落として終える。
8. **全キャラに「欲しいのに受け取れないもの」を1つ持たせる。** ここからコメディと情が同時に出る。
9. **関係はバリア（外形的な壁）で持たせる。** 感情の不足で持たせない。
10. **対等でない相手と戦わせない。** ミミと裏ボスは追いかけっこではなく、対等な立場でぶつかる。

## 7. やってはいけないこと（現状の失敗の再発防止）

1. 最終ノードで全部を着地させる（「上出来の一日だった」型）。→ §3-1
2. 1話の中に発端・葛藤・解決を全部詰める。→ **1話は場面ひとつ、または場面ひとつ＋その反応**しか入らない。
3. 1話の中で時間・場所を3回以上飛ばす。→ ep1 は朝→昼→午後→夕方→帰りで5回。**上限は2回。**
4. 行為の報告文を並べる（世界の刺激だけ／ミミの行為だけが3行以上続く）。→ §2-2、§1-1 行8
5. 固有名詞を出すだけで、それが何かを見せない。→ §4-1
6. 設定を3行以上まとめて説明する。→ §2-1
7. ミミが驚いた瞬間に読者も初めて知る（サプライズ設計）。→ §4-3
8. 前話の要素を「先週こうでした」と要約で受ける。→ §5-1
9. **新事実の追加を「理解が深まった」と数える。** → §1-1 行6、§8-3
10. 大会を「勝ちたいから勝つ」で動機づける。→ 【二】§3
11. 「あなたが選んだ」「今週の結果」「この選択が残したもの」などの因果整理ラベル、`CURRENT`/`NEXT`/`RESULT` 等の眉見出し。→ マニフェスト
12. 選択後に報告書型の結果画面を挟む。→ マニフェスト
13. 職場のいじめ・退職予想・陰口・社内評価を葛藤や感動の主題にする。→ マニフェスト
14. 同じ書式で13話が始まる（予告編化）。→ §5-3
15. 答えを決めていない謎を投げる。→ §4-4

## 8. 各話の完成チェックリスト

## 3. 大会への動機を物語側で育てる仕組み

### 3-1. 大会は3週で1組にする（週N-1 / 週N / 週N+1）

| 週 | 役割 | 必須要素 |
|---|---|---|
| **N-1（前週）** | 予告 | **締切を一個の物にして画面に出す**（掲示板の日付、貼り出された組み合わせ、届の受理印、賭け率表）。「大会が近い」と地の文で書かない |
| **N（当週）** | 試合 | 決着は**読者がすでに理解している規則だけ**で付ける。新しい規則で勝たせない |
| **N+1（翌週）** | 余波 | **既知の人物の生活が具体的にどう変わったか**を1つ見せる。これが進捗の道標になる |

### 3-2. 「勝ちたいから勝つ」の禁止と、賭け金の階段

各大会の前週に、**〈勝ったら得るもの／負けたら失うもの〉を人物の口から一度だけ**言わせる。地の文で整理しない。

| 大会 | S1（欠落の回避） | S2（そこでしか手に入らないもの） | S3（意味の反転） |

| 週4 | 出ないと**席**を失う | 出ないと**去年の記録**が閉じる | 出る意味を疑う |
| 週8 | 個人の賞品（道具・許可） | この街の成り立ちに触れる権利 | 相手のために出る |
| 週12 | 周囲への波及（誰かの職が懸かる） | 誰かの正体が懸かる | 勝敗が問題でなくなる予兆 |
| 週16 | 他人の生活が懸かる | 街の規則そのものが懸かる | 規則を書き換える権利 |

### 3-3. 二層の欲望

- **意識的欲望**（筋を駆動）：勝つ・稼ぐ・生き延びる。毎週変わってよい。
- **無意識の必要**（意味を与える）：**名前を持つこと／帰る場所／自分で決める権利**。26週不変。
- **無意識の必要は、ミミより先に読者へ見せる。** 週2〜3で、ミミが自覚していない形（他人の台詞、ミミが無意識にやってしまう行動）で提示する。

## 4. 週13（中点）の仕様

26週で最も重要な週。**以下4つを同一の話に同時に負わせる。**

1. **偽の勝利**：ミミは求めていたものを手に入れる（勝つ／認められる／答えを得る）
2. **鏡の瞬間**：得た直後にミミが自分を見る。「自分は何になろうとしているのか」を**感情とともに**直視する

## 6. シーズンをまたぐ連続性

### 6-1. 三周の縦の作り

- **S1（愛着）**：世界の作法を体で覚える。人と物に愛着が付く。ミミも読者も、街を「面白いところ」と思って終わる。
- **S2（不思議＋大目標）**：**S1で愛着が付いた物・人・出来事の意味が反転する。** S1で笑ったことが、S2で別の顔を見せる。大目標をここで達成する。
- **S3（覚醒と大団円）**：ミミが規則を書く側に回る。全員に道筋を用意して閉じる（バッドエンドを書かない）。

### 6-2. またぎの具体装置（3つ）

1. **同じ物を三回出す。** S1で笑いの道具として、S2で謎の証拠として、S3で決着の道具として。**毎回違う理由で、強調せずに触れる。** 台帳に「物／S1の用途／S2の用途／S3の用途」を登記する。
2. **同じ場面を、一語だけ変えて再演する。** S1の週1とS2の週1を同じ場所・同じ台詞で開き、**一語だけ違う**。ミミは違和感を持つが説明しない。読者だけが気づく。
3. **周回を跨ぐ実績（`seenEvents`）を、劇中の物で見せる。** 「知っているはずのないことを知っている」状態を、システムの表示ではなく、**ミミの手が先に動く**形で書く（「棚の三段目に手が伸びた。まだ誰にも教わっていない」）。

### 6-3. 周回で必ず不変にするもの

**大きな物語ビートの順序は、周回数や進み方に関わらず同じ順に当たる。** 周回差は「条件付きの反応」と「いつでも出せる雑談」の層だけで吸収する。三層で管理する。

| 層 | 中身 | 周回差 |
|---|---|---|
| **必須ビート** | 週1・2・4・7・13・20・25・26 とすべての大会週 | 不変 |
| **条件付き** | 直前の勝敗・訓練・選択・出会った人物に反応する話 | 変わる |
| **常緑** | いつでも出せる小話・雑談 | 変わる |

## 7. ミミが世界を理解していく段階の設計

**「知識が増える」を段階の指標にしない。段階は「規則との関係」で測る。**

| 段階 | ミミの位置 | その段階で書けること | 該当区間 |
|---|---|---|---|
| **1 規則を知る** | 規則に従う | 「この街ではこうする」を体で覚える | S1 週1〜7 |
| **2 代償を知る** | 規則に払う | 規則には必ず代価があると分かる。従っただけでは損をする | S1 週8〜13 |
| **3 例外を知る** | 規則を使う | 規則の抜け道と、抜け道を使ったときに誰が損をするかが分かる | S1 週14〜26 |
| **4 目的を知る** | 規則を疑う | 「なぜこの規則があるのか」「誰のために作られたのか」が分かる | S2 全域 |
| **5 引き受ける** | 規則を書く | 自分が決める側に立ち、その責任を負う | S3 全域 |

### 7-1. 段階を進める唯一の書き方

**各話に「予期 → 行動 → 世界の別の反応」を通す。**

1. ミミが「世界はこうなっているはずだ」と**行2で言い切る**
2. その前提で**行3〜5で動く**
3. 世界が**行6〜7で別の反応を返す**
4. **次話の行2では、更新後の前提でミミが振る舞っている**

情報を渡すだけでは世界模型は更新されない。**予期を明示していない話では、何を知っても理解は深まらない。**

### 7-2. 新語より深さ

- **各シーズンで新しい用語は最大でも区分あたり1つ。** 新語を足す前に、既出の一つに**弱点・代償・例外**を与える。
- 理解が深まるとは、**規則の代償・例外・裏面を知ること**であって、規則の数が増えることではない。
- **決着は、読者がすでに理解している規則だけで付ける。** 新しい規則で勝たせない。新しい規則は、使う話より**前の話**で、使われている形で見せておく。

## 8. 着手条件と運用

### 8-1. 書き始める前に決めておくこと（これが揃うまで本文を書かない）

### 8-4. 監査スクリプトへ落とせる項目（`src/narrative/audit.ts` の候補）

- フィルター語・思考動詞の出現数（1話3個以下）
- 一文の最大字数（40字）と平均字数、3行以上の文の検出
- 漢字使用率（20%以下）
- 「そして」「……」「――」の回数（各1回以下）
- 非視覚知覚語の辞書一致が1話2つ以上あるか
- `debug.authorNote` のメタ行の必須キー（Q / value / turn / hook / try / game / carry / open / close）の存在
- `value` の符号が変化しない話の検出
- 各話の末尾ノードが、その話の最短ノードであることの検査
- 前話の `open` の語が、次話の先頭2ノードに再出しているかの照合
- `newterm` が同じノード内で機能語（決まり・届く・負けたら・断れない 等）と共起しているか
- `hook` の型・切断位置が3話連続で同じでないか
- 週4〜21 に `try=はい、そして` が出ていないか
- 同時に開いている糸の総数が6本以上になっていないか

### 8-5. 改稿の最小着手順序（既存26話を直すとき）

1. **全話の最終ノードだけを書き直す**（§3）。これだけで連続感は即座に出る。工数最小・効果最大。
2. **フィルター語と知覚描写の機械的置換**（§2）。文単位の作業。
3. **各話の行6を「認知＋逆転」へ設計変更**（§1-1、§7-1）。ここが最も工数が大きい。
4. 週7・13・20・25・26 の5話を仕様どおりに作り直す。
5. 大会7回を3週1組（§3-1）へ組み替える。
