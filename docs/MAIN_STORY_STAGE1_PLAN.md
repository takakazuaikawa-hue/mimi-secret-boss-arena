# 第一勤務週・メインストーリー骨子「注文番号・零〇一」

三段階キャンペーン(docs/GAME_DESIGN.md §4 / src/data/campaignStages.ts)の
第一区分の背骨。再生は常に**メインストーリー→続けて個別ストーリー**の二段構え。
個別7場面(改稿済み)は一切書き換えず、その入口へ橋を架けるだけにする。

## 0. 原則

- 表向きの目的は一つだけ: **「閉店までに、三百年前の注文を一件処理する」**。
  ポイントカード・派遣・移譲・大会などの説明項目は、この仕事を終わらせようと
  した結果の**事故の連鎖**として発生させる(説明として並べない)。
- 世界の異常は**現象だけ**で見せる。「終わった物語」「クリア後」等の命名は
  中盤(第二区分以降)まで作中人物に言わせない。
- 感情の中心はギドノ一人。残り4人は「名前を覚えられる一場面」と
  「次に会いたくなる未解決の一言」に絞る(均等に描かない)。

## 1. 事件の核

カジノカフェの注文管理システムに、未処理のまま**三百年**残っている
最古の注文が一件ある。注文番号・零〇一。品名「限定パフェ(一名様)」。
ミミの初日の業務はこれを「処理」すること——受理でも取消でもよい、
とにかく台帳から消すこと。だが処理しようとするたび、闘技場の各部署で
事故が連鎖し、5人の裏ボスが別々の立場からこの注文に関わっていく。

最終話でパフェは「提供」される。三百年待った客の窓口で、ミミは
取消ではなく提供を選ぶ——これが第一区分の背骨の締めで、
初心者大会(第4週)への接続点になる。

## 2. 全5話の構成(メイン側)

各話の末尾は、既存meetの実際の入口(場所・業務)を発生させて終わる。
個別側の冒頭と時系列・場所が完全に噛み合うことを確認済み。

| 話 | 仮題 | 内容 | 橋(既存meetの入口) |
| --- | --- | --- | --- |
| 第1話 | 未処理・三百年 | 初日。台帳の最古の注文「零〇一」を発見。発券機の今日の一枚目が、なぜか**二番**(一番は三百年前に発行されたまま戻っていない)。閉店までに処理せよ、が本日の業務 | 閉店五分前のカフェ、窓際に整理券**「一番」**の客(ギドノ meet「窓際、ひとつ空けて」へ) |
| 第2話 | 引換券は遺失物 | 注文零〇一の引換券が見つからない。台帳いわく「遺失物扱い」。発行日が三百年前なのに、字が乾いていない | 本日の担当は遺失物窓口(ミナト meet「遺失物、勇者の剣四十七本」へ) |
| 第3話 | 三百年目の納品 | 零〇一の材料が「本日入荷」で届き続けていたことが判明。最後の一箱が搬入口に着く。受け取りサインが要る | 搬入口の「彫像さん」へサインを頼みに行く(丁零 meet「命令待機、四百時間」へ) |
| 第4話 | 行列と迷子 | 幻のパフェ提供の噂が広まり行列が発生。列に並んでいたお子様が迷子に | 迷子のお迎え要請で案内所へ(ピオニー meet「紙の冠と、全力の指先」へ) |
| 第5話 | 記念写真の五人目 | 提供準備の記念撮影を手配。書庫で見つけた三百年前の「受付時の記念写真」の隅に、見覚えのない影がひとり写っている | 撮影所から苦情対応の応援要請「127枚全部に写ってはいけない人が」(うしろ meet「百二十七枚の、写り込み」へ) |

第5話の末尾でパフェ提供(=事件の畳み)。三百年前の写真の影と、今日の
写り込みが同じ姿であることは、言葉にせず写真の並びだけで見せる。
以後のメイン枠は大会・移譲イベント(既存)へ譲り、個別ストーリーが主役になる。

## 3. 異常の種(言葉で説明しない現象)

序盤に散らす「ここ、何かおかしい」だけを作る現象。命名・解説は禁止。

- 発券機の今日の一枚目が**二番**(第1話)→窓際の客が「一番」を持っている
  (既存meetの整理券「一番」の描写を回収として活かす。meet本文は不変)
- 注文伝票の「受付者」欄の筆跡が、ミミの字に似ている
- 開催前の初心者大会に「二度目の優勝記録」が既にある
- 三百年前の記念写真に、今日と同じ影が写っている(第5話)
- 遺失物窓口の引換券のインクが乾いていない(第2話)

## 4. 橋の設計(メイン→個別の接続規則)

- メイン各話の末尾は、その週の個別場面(meet)の**入口の状況を発生させて**終わる。
  個別側の本文は変更しない(参照安全規則は現行のまま)。
- 個別場面が先に消化済みの周回(やり直し時)は、メイン側の末尾一行だけ
  差し替え(「もう知っている顔だ」系の受け)で矛盾を防ぐ。
- 4人の脇役はメイン側では**一場面+一言**まで。掘り下げは個別へ委ねる。

## 5. 実装(二段再生)

既存の連続再生パターン(所有権移譲→温泉旅行)をそのまま踏襲する。
新しい保存フィールドは不要。

- **メイン話の差し込み**: `chooseWeeklyAction` の週固定イベント前例
  (`hotSpringTripScene`: week+flags+eventHistory 判定)と同型で、
  区分1かつ該当週・未再生ならメインブロックを `currentEvent` にする。
- **個別への連続再生**: `continueEvent` の followup 連鎖
  (`maybeCreateOpeningOwnershipFollowup` / `maybeCreateLiberationFollowup`)に
  `maybeCreateMainStoryFollowup` を追加。メイン話の終了直後に、橋先人物の
  meet 場面(`sceneForStage(fighterId, 0)`)を次の `currentEvent` として返す。
  xstate は既存の OUTCOME_FOLLOWUP → event 遷移をそのまま使う。
- **ブロック登録**: kind は既存 `"opening"` を使い(新kindは追加しない)、
  `src/narrative/content/main.s1.ep1.json` 〜 `ep5.json` を
  `openingBlocks.ts` へ登録。`content.ts` の総数監査を+5更新。
- 進行管理は `run.eventHistory`(once-per-run)と週番号で行い、
  新フラグは最小限にする。
- 既に橋先人物が遭遇済みの周回(区分やり直し)では、followup を出さず
  メイン話単独で終わる(末尾の受け行のみ分岐)。
- 導入(OPENING_COMMON_SCRIPT_V2)の圧縮は本計画の第1話と統合する。
  表向きの目的の一本化により、35ページの説明項目を事故の連鎖へ組み替える。

## 6. 完了条件

  実装 → 実画面で第1週(メイン→ギドノmeet連続再生)を通し確認。
